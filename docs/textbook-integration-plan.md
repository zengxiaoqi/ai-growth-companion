# 教材整合方案：ChinaTextbook × book-to-skill × 灵犀伴学

> 创建日期：2026-07-20
> 最后更新：2026-07-21
> 状态：Phase 1 验证完成，进入问题修复阶段

## 一、概述

将人教版教材（TapXWorld/ChinaTextbook）通过 book-to-skill 蒸馏为结构化知识，整合到灵犀伴学中，实现：
- AI 助教回答**基于教材**，杜绝幻觉
- 课程自动对齐国家教学大纲
- 互动游戏内容有据可依

## 二、三个项目的关系

```
ChinaTextbook（教材 PDF）──→ book-to-skill（PDF → Agent Skill）──→ 灵犀伴学（互动学习 App）
       ├ 人教版小学~大学          ├ 提取章节/知识点/框架          ├ AI 助教问答
       ├ 数学/语文/英语等          ├ 生成 SKILL.md + 章节文件       ├ 自动生成互动课程
       ├ 75.7k stars              ├ 每章 ~1K tokens               ├ 7 种游戏类型
       └ 14GB+ PDF 集合           ├ 8.7k stars / MIT              ├ Flutter + NestJS
                                   └ ~$1/本书 LLM 处理费           └ AI 聊天 + 诗词鉴赏
```

## 三、技术方案

### 3.1 数据流

```
教材 PDF ──→ book-to-skill 离线处理 ──→ Skill 文件夹（结构化知识）
                                             │
                                             ├─→ SKILL.md（核心框架 ~4K tokens）
                                             ├─→ chapters/（每章 ~1K tokens，按需加载）
                                             ├─→ glossary.md（术语表）
                                             ├─→ patterns.md（模式/方法库）
                                             └─→ cheatsheet.md（速查表）
                                                    │
                                                    ├─→ 后端 AI 服务加载 Skill
                                                    │       ├─→ AI 聊天（教材级回答）
                                                    │       └─→ 课程生成器（互动课程）
                                                    │
                                                    └─→ Flutter 端
                                                            └─→ 辅助阅读/参考功能
```

### 3.2 集成方式

**方式一：离线预处理（推荐，先做这个）**
- 一次性把教材 PDF 跑 book-to-skill 生成 Skill 文件
- Skill 文件存入后端 `data/textbook-skills/` 目录
- 后端 AI 服务按需加载对应章节
- 优点：零运行时开销，无外部依赖

**方式二：后端子进程调用**
- 用户自定义教材上传时，通过 `child_process.exec` 调用 book-to-skill
- 实时生成 Skill 并缓存
- 优点：灵活，支持用户自传教材

**方式三：微服务包装**
- 将 book-to-skill 包装为独立微服务（FastAPI）
- 后端通过 HTTP 调用
- 优点：解耦，可独立扩展

## 四、实施步骤

### Phase 1: Proof of Concept（当前阶段）
**目标：验证 book-to-skill 的教材处理效果**

1. 克隆 book-to-skill 仓库
2. 下载一本教材 PDF（选小学数学一年级上册，文件最小）
3. 安装依赖（pypdf 等）
4. 运行 book-to-skill 处理该 PDF
5. 评估输出质量：
   - 章节结构是否完整？
   - 知识点提取是否准确？
   - 每章摘要是否可用？
   - 术语表是否覆盖关键概念？
6. 将生成的 Skill 接入灵犀伴学 AI 聊天，对比有无 Skill 的回答质量

**验收标准：** 生成的 Skill 能正确识别教材章节，AI 基于 Skill 的回答准确率 > 90%

### Phase 2: 批量处理
**目标：覆盖小学到初中所有数学教材**

1. 从 ChinaTextbook 下载全部数学教材 PDF
2. 编写批量处理脚本（`scripts/batch-process-textbooks.sh`）
3. 逐一运行 book-to-skill，生成 Skill 文件
4. 建立 Skill 索引（按年级/学期/学科）
5. 验证每本教材的 Skill 质量

**涉及教材数量：** 小学 12 册 + 初中 6 册 = 18 册数学教材
**预计成本：** ~$18-25（按 ~$1/本计算）

### Phase 3: 后端集成
**目标：Skill 文件可被后端 AI 服务按需加载**

1. 创建 `TextbookSkillLoader` 服务
   - 读取 Skill 文件目录结构
   - 按年级/学科/章节查询
   - 加载对应章节内容到 AI 上下文
2. 接入 AI Chat 模块
   - 用户提问时，自动检测相关教材/章节
   - 加载对应 Skill 内容，生成教材级回答
3. 接入课程生成器
   - 以 Skill 的章节结构为大纲
   - AI 自动生成互动课程（Quiz、Matching 等）

### Phase 4: 前端功能
**目标：用户可感知的教材整合功能**

1. 学习页面增加"教材同步"入口
2. 选择年级 → 显示对应教材章节列表
3. 点击章节 → 进入互动课程（自动生成）
4. 题目做错时 → 显示教材对应知识点
5. AI 聊天中默认加载当前年级的教材 Skill

### Phase 5: 教育网站对接
**目标：对接官方教育平台，获取最新教材**

#### 5.1 可对接的教育网站

| 平台 | 说明 | 接入方式 |
|------|------|---------|
| **国家中小学智慧教育平台** (basic.smartedu.cn) | 教育部官方平台，有最新版电子教材 | 网页爬取（需关注反爬策略） |
| **人民教育出版社** (pep.com.cn) | 教材出版社官网，教材更新源头 | 直接下载或 RSS 监控 |
| **学科网** (zxxk.com) | 教育资源平台，含大量配套资源 | API 对接（需商务合作） |

#### 5.2 教材更新策略

- **版本检测**：定期检查官方平台是否有新版本教材发布
- **增量更新**：发现新版本后，自动下载并重新处理
- **版本管理**：后端保留多版本教材，用户可切换
- **通知机制**：教材更新时通知家长端

#### 5.3 技术实现

```
教材更新检查器（cron 定时任务）
    │
    ▼
检查官方平台版本号
    │
    ├─ 版本未变 → 跳过
    └─ 版本更新 → 下载新 PDF → 运行 book-to-skill 处理 → 更新索引
```

### Phase 6: 用户上传文件
**目标：支持用户自行上传教材/学习资料**

#### 6.1 上传流程

```
用户在 Flutter 端选择文件
    │
    ▼
上传到后端（PDF/EPUB/DOCX/Markdown）
    │
    ▼
后端接收 → 文件校验（格式、大小、完整性）
    │
    ▼
后台任务：运行 book-to-skill 处理
    │
    ▼
生成 Skill 文件 → 存入用户专属目录
    │
    ▼
通知用户处理完成
    │
    ▼
AI 可基于该 Skill 回答用户关于此文件的问题
```

#### 6.2 技术要点

| 项目 | 方案 |
|------|------|
| 文件存储 | 后端本机 `data/user-uploads/{userId}/` 或对象存储 |
| 文件大小限制 | 暂定 100MB（PDF 压缩后通常 <50MB） |
| 支持格式 | PDF、EPUB、DOCX、TXT、Markdown |
| 处理方式 | 后台队列异步处理（避免阻塞请求） |
| 处理结果 | 结构化 Skill 文件 + 元数据记录到数据库 |
| 并发限制 | 同一用户同时最多 3 个任务 |

#### 6.4 用户上传 vs 内置教材对比

| 维度 | 内置教材（ChinaTextbook） | 用户上传 |
|------|--------------------------|---------|

## 五、技术选型说明

### 为什么选 book-to-skill 而不是 RAG

| 维度 | book-to-skill | RAG |
|------|--------------|-----|
| 处理时机 | 编译时（一次性） | 查询时（每次） |
| 输出形式 | 结构化框架 | 向量片段 |
| Token 开销 | 每章 ~1K | 每次检索 ~N 个 chunk |
| 回答质量 | 框架级推理 | 相似度匹配 |
| 适用场景 | 深入学习某本书 | 跨文档搜索 |

教材是"窄而深"的场景——孩子反复学同一本教材——适合 book-to-skill 的编译时思路。

### 为什么不用直接 PDF 阅读

| 方式 | 问题 |
|------|------|
| 直接看 PDF | 无交互，无 AI 辅助 |
| PDF 全文塞进 AI 上下文 | 每次烧大量 token |
| 人工整理知识点 | 不可持续 |

## 七、PoC 验证结果与修复计划

### 7.1 PoC 验证结论

**测试文件：** 人教版《数学六年级下册》PDF（122 页，12.5 MB）
**提取工具：** book-to-skill scripts/extract.py（pypdf 引擎）

**验证结果：** 核心文本提取可行，但存在以下问题需要修复：

| # | 问题 | 严重程度 | 修复方案 |
|---|---|---|---|
| 1 | 章节标题格式不匹配 | 🔴 高 | 自定义 parser 适配 `第N单元`、`N 标题` 格式 |
| 2 | 汉字间多余空格 | 🔴 高 | 后处理：去除全角汉字间空格 |
| 3 | 表格结构丢失 | 🔴 高 | 安装 Docling（layout-aware 提取） |
| 4 | 数学公式/上标丢失 | 🟡 中 | Docling 可部分解决 |
| 5 | 目录检测失败 | 🟡 中 | 适配中文"目 录"格式 |
| 6 | 图片/插图无法提取 | 🟡 中 | 超出纯文本提取范围，以文字描述替代 |

### 7.2 修复计划

1. 在灵犀伴学项目中创建 `scripts/textbook/` 目录
2. 编写 `process_textbook.py` 脚本，包含：
   - 个性化 parser（适配人教版章节格式）
   - 后处理清洗（去空格、修复符号）
   - Docling 集成（布局感知提取）
   - 输出结构化 JSON
3. 测试 5 本以上教材验证泛化性

## 六、风险和应对（续）

| 风险 | 影响 | 应对 |
|------|------|------|
| 扫描版 PDF 提取质量差 | 语文、部分数学可能识别不准 | 先用文本版 PDF（数学教材有文本层）；扫描版后续用 Docling OCR |
| book-to-skill 对中文支持 | 术语表、章节识别可能有问题 | PoC 阶段验证；必要时 fork 修改 |
| 教材改版 | 内容过时 | 教材知识体系相对稳定（小学数学近 10 年未大改）；定期检查 ChinaTextbook 更新 |
| 版权问题 | 商业使用风险 | 仅用于个人学习场景；不直接分发 PDF 内容；Skill 是衍生知识而非原文 |
| LLM 费用 | 批量处理 ~$20 | 一次性成本，后续运行时零成本 |
