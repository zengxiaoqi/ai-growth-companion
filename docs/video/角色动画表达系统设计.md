# 角色动画表达系统设计（根治"大头像 + 小图标"）

> 触发问题：教学视频前两幕（"小熊来公园""爬上滑梯"）呈现为一只占半屏的动物头像，
> 旁边配一个与角色毫无空间关系的小图标。第 3、4 幕（滑梯、拍球）因为有 3D 舞台而正常。
> 本文不从这两幕下手，而是回答一个问题：**为什么系统只能产出这种画面，以及要改哪一层才能不再产出。**
> 文档状态：设计稿。对应仓库代码位置均为当前版本。

---

## 1. 结论先行

前两幕不是"分镜写坏了"，也不是"模板没调好"。它们暴露的是同一个结构性缺口：

**系统里"角色"只有两种极端形态——静态头像徽章，或 3D 全身骨架；中间缺一层"2D 全身可动角色"。**

- 头像徽章（`ActorFigure`，320×320 圆形）没有躯干、没有腿、没有可动关节，物理上表达不了"爬""走""蹲""站"；
- 3D 骨架（`ThreeActionStage`）能表达，但只对 `slide` / `dribble` 两个动词开放，且成本高（每帧光栅化）；
- 两者之间没有过渡，于是任何"单人连续动作"要么掉进徽章（假动作），要么根本没有表达（兜底 emoji 卡片）。

而更深一层的问题在于：**姿态解算被私有化在 3D 渲染器内部**。`slidePose()` / `dribblePose()`
写在 `ThreeActionStage.tsx` 里，产出的是 `root / handL / handR / footL / footR / rotZ / headTilt`
——这已经是一份与渲染器无关的抽象姿态，却被锁在一个渲染器里。2D 拿不到它，只能自己另写一套
"沿斜线平移 + 旋转 24 度"的假动作。

**所以系统性解法不是再写一个 2D 动作分支，而是把姿态解算提成中枢，让所有渲染器消费同一份姿态。**

一句话概括目标：

> 动作只描述一次（姿态曲线），渲染器只负责投影（3D 几何 / 2D 分片 / 头像徽章）。

## 2. 现场证据

### 2.1 第 1 幕：徽章 + 说话气泡

渲染路径：`interaction.verb = speak` → `ActionStage` → `ActorFigure`。
`ActorFigure` 的实际结构（`video-generation-agent.service.ts:1822-1868`）：

- 一个 `320×320` 的白色圆形，内嵌一张 `assets/vector/animals/bear.svg`（`288×288`）
- 一条代码画的"手臂"：一根 `strokeWidth=24` 的竖线 + 一个圆（`:1862-1865`）
- 位移只有 `bob = sin(frame/14)*7`、`lean` 前倾、`armAngle` 摆动

也就是说，"角色"是一张贴图装进圆框，唯一的肢体是一条贴上去的棍子。**它没有腿，所以"走进公园"演不出来，只能弹入。**

### 2.2 第 2 幕：根本没有表达路径

该幕在 manifest 里长这样（`task-2-*/props.json`）：

```
scene2 | 爬上滑梯 | interaction: none | figure: none | graph: none
```

`interaction` 为空的直接原因是分镜 schema 的语义边界：`generate-video-content.ts:335`
把 `interaction` 定义为「**两个角色之间**的动作」（pass / lift together / talk / point）。
"小熊一步一步爬上滑梯"是单人动作，模型按契约判定"不需要 interaction"，于是留空。

留空后渲染落在 `SceneLayer` 的最后兜底分支（`:2170-2189`）：一张 `480×320` 白卡片 +
一个 120px emoji + 六个绕轨道转的小圆点。**这不是"弱"，这是没有任何语义。**

### 2.3 第 3、4 幕为什么正常

`interaction.verb = slide / dribble` → `hasInteraction` → `action3d` → `ThreeActionStage`。
它有完整骨架：`ProceduralChar` 画头/躯干/双臂/双腿，四肢按「肩 → 目标点」定向，
所以掌球接触、臀部贴滑面都是**算出来的**。

**同一个系统，能演出接触与位移的那条路径，恰好是唯一的 3D 路径。这不是巧合，是架构决定的。**

### 2.4 现有的 if 链

`SceneLayer`（`:4093-4106`）的表达选择完全由"哪个字段非空"决定：

```
hasFigure        → FigureStage（受控画板的静态图元）
use3d            → ThreeActionStage（仅 slide / dribble）
hasInteraction   → ActionStage（6 个 verb 分支，全部摆同一枚徽章）
hasGraph         → SceneGraphStage
else             → 白卡片 + emoji
```

这是**事实驱动的级联**，不是**意图驱动的匹配**。新增一种表达方式就要在这条链上插一层，
且新动作必须在 `ActionStage` 里再加一个 `if (it.verb === ...)`（当前已有 7 个）。

## 3. 根因归纳

| # | 结构性缺陷 | 代码位置 | 后果 |
|---|---|---|---|
| R1 | 姿态解算私有化在渲染器内 | `ThreeActionStage.tsx:469` `slidePose`、`:544` `dribblePose` | 2D 无法复用，只能造假动作；新增动作要写 N 遍 |
| R2 | 角色形态只有「贴图徽章 / 3D 骨架」两档 | `ActorFigure`、`ProceduralChar` | 缺 2D 全身，中间表达断层 |
| R3 | 单人动作没有归属字段 | `generate-video-content.ts:335` 把 interaction 限定为"角色之间" | "爬/走/跳"无处安放，整幕静默降级 |
| R4 | 表达选择是字段级联，不是能力匹配 | `SceneLayer:4093-4106` | 新动作=新分支，分支数线性膨胀，且必须改渲染器 |
| R5 | 道具是"角落图标"，没有可附着表面 | `PropArt`（`:1698-1782`）返回一个 `<g>` | "爬上滑梯"没有落点，只能并排放着 |
| R6 | 没有构图层（景别） | 全局固定布局 | 头像徽章被当成全身用，特写与全景同构 |

R1 是主因：**它让 R2 的断层无法被低成本填平**。如果姿态在中枢，2D 侧只需要写"怎么画"，不需要写"怎么动"。

## 4. 目标架构

### 4.1 三段式管线

```
① 意图     performance: { actor, motions:[{op, params}] }
              ↓  原语校验（白名单 + 参数越界丢弃 + 可演性检查）
② 时间轴   MotionTrack: t → pose
              ↓  pose 中枢（与渲染器无关）
③ 投影     Stage3D | Puppet2D | Badge
              ↓
           像素
```

现状 = ① 在正则里、② 在 3D 组件里、③ 有三套互不相干的实现。
目标 = ② 成为唯一真源，①③ 都围着它。

### 4.2 Pose 契约（跨渲染器）

沿用 3D 已有的 `Pose`，只补两处（躯干旋转与注视方向），其余不动：

```ts
interface Pose {
  root: Tri;            // 髋部世界坐标
  rotZ: number;         // 躯干倾角（弧度）
  rotY: number;         // 朝向（0 = 正对镜头）
  handL / handR: Tri;   // 相对髋部的手部目标点
  footL / footR: Tri;   // 相对髋部的脚部目标点
  headTilt: number;
  tailSwing: number;
  squash: number;       // 压缩/拉伸
}
```

**关键性质：这是"关节目标点"，不是像素。** 3D 用四元数把肢体指向目标点（已有实现）；
2D 把目标点投影到画面坐标后，用「髋 → 目标」的向量直接算两段肢体的肘/膝位置。
同一份结构，两种投影。

### 4.3 动作原语（有限集 + 参数）

动词是语义，原语是运动学。一个原语可以有多种节奏参数，不必为每个新动词写新分支。

| 类别 | 原语 | 参数 | 2D | 3D |
|---|---|---|---|---|
| 位移 | `enter` | from, distance, speed | 从画外走入 | 同 |
| 位移 | `walk` | distance, speed, stopAt | ✔ | ✔ |
| 位移 | `climb` | surface(rung[]), steps, rise | ✔ | ✔ |
| 位移 | `slide` | surface(ramp), from, to | ✔ | ✔（已有） |
| 位移 | `jump` | height, count | ✔ | ✔ |
| 操作 | `hold` | prop, hand | ✔ | ✔ |
| 操作 | `bounce` | prop, count, height, hand | ✔ | ✔（已有） |
| 操作 | `handover` | prop, from, to, arc | ✔（已有） | ✔ |
| 操作 | `push` | prop, distance | ✔ | ✔ |
| 手势 | `wave` | amp, reps | ✔ | ✔ |
| 手势 | `point` | target | ✔ | ✔ |
| 手势 | `speak` | text, bubbleSide | ✔（气泡是 DOM） | 气泡仍走 DOM |
| 状态 | `idle` / `sit` / `stand` / `cheer` | — | ✔ | ✔ |

新增一个动作 = 加一个 `pose(op)` 函数 + 注册原语。**不改 `SceneLayer`，不改任何渲染器的 if 链。**

### 4.3.1 写死的是字母表，不是句子

这一节回答"原语表是不是又一套死枚举、遇到新动作怎么办"。

**必须区分两件事：运动学实现（怎么动）与动作编排（做什么）。**

`pose()` 是运动学实现：给定时间和参数，算出髋部位置、四肢目标点、躯干倾角。
这部分不能交给模型，理由和"不让模型写 SVG"一样——每帧都要算、必须确定、
错了要静默降级。所以它写在代码里，且**永远只有约 24 条**（走/跑/爬/滑/跳/进/出、
拿/放/递/拍/推/举、挥/指/说/点头、站/坐/蹲/躺/欢呼）。

但**动作编排是开放的**，靠四级机制，前三级都不改一行代码：

| 级别 | 谁做 | 例子 | 改动面 |
|---|---|---|---|
| L1 参数化 | 分镜模型改参数 | "慢慢爬" → `climb{speed:0.6, steps:4}` | 0 |
| L2 组合 | 分镜模型串原语 | "爬上去再坐下" → `[climb, sit]` | 0 |
| L3 关键帧 | 分镜模型给 3–5 个姿态关键帧 | "转个圈" → 3 帧 `Pose` | 0（有物理校验） |
| L4 新原语 | 人写一次 `pose()` | "游泳" → `swimPose()` | 1 个文件 |

**L3 是真正的逃生舱**：模型不需要认识 `spin` 这个原语，只要输出
`[{t:0,...stand}, {t:0.5, rotY:π}, {t:1, ...stand}]`，代码做插值。
`Pose` 本来就是关节目标点，天然适合让模型填——但填的是**相对值 + 归一化参数**，
不是世界坐标，且必须过四道物理校验才会被采用：

```
脚不穿地（footY ≥ 地面） / 手不超臂长（|hand-肩| ≤ armLen） /
重心在支撑面内（髋部投影落在双脚之间或锚点上） / 关节角不反向
```

任一项不过就整份丢弃，回落到最近邻原语并 `warn`。**不允许静默成 emoji**——
那正是今天第 2 幕的病。

### 4.3.2 反向闭环：把能力表回灌给生成端

比"无限扩展动作"更划算的是"让生成端知道什么能演"。

`generate-video-content.ts` 的 system prompt 里应注入当前渲染器的原语清单与参数范围
（即能力表），要求模型在可演空间内写分镜。于是：

- "小熊蹦蹦跳跳跑过去" → 模型自己选 `[walk, jump]`，而不是写一个引擎没见过的动作
- 真的写不出来时，模型改写表达（"小熊慢慢地走过去"），叙事等价、可演性更高

这条闭环一旦建立，**"新动作"的绝大多数需求会在生成端被消化**，不需要动渲染层。
当前的静默降级之所以发生，正是因为生成端完全不知道渲染端有什么能力。

### 4.4 能力匹配（替代字段级联）

渲染器声明能力，选择器按"这一幕所需原语集合 ⊆ 渲染器能力"取成本最低者：

| 渲染器 | 支持原语 | 成本 | 适用景别 |
|---|---|---|---|
| `Badge` | 仅 `speak` / `wave` / `idle` | 最低 | 仅 close-up |
| `Puppet2D` | 全部 2D 可投影原语 | 低 | medium / wide（**默认**） |
| `Stage3D` | 需要真实接触/三维透视的原语（`slide`/`bounce` + `depth` 标记） | 高 | wide（重点幕） |
| `Figure` / `Graph` | 非角色场景（图形即知识） | 低 | — |

选择伪码：

```
need = motions.map(m => m.op)
if (isKnowledgeFigure(scene)) return Figure/Graph
if (need ⊆ Badge.caps && shot === 'close') return Badge
if (need ⊆ Stage3D.caps && requiresContact(need)) return Stage3D   // 显式 opt-in
return Puppet2D                                                     // 默认
```

**为什么默认是 Puppet2D 而不是 3D**：3D 每帧光栅化，40 秒片子 3D 幕占比越高出片越慢；
而绝大多数教学动作（走、指、递、挥手）在 2D 分片骨架上完全够用，且更接近儿童绘本的画风。

### 4.5 2D 全身角色的投影规则

分片结构（一个 `bear.svg` 拆成 6 片，全部围绕髋部定位）：

```
head + ears + muzzle   ← headTilt 旋转
torso                  ← rotZ 旋转
armL / armR            ← 髋→手目标点，两段（上臂+前臂），肘部用固定弯向
legL / legR            ← 髋→脚目标点，两段，膝部同理
```

两段肢体的中间关节用固定弯向求解（例如膝盖恒向后），这是 2D 动画的标准做法，
避免 IK 自由度导致的抖动。**画面里看到的是"肢体的朝向变了"，不是"贴图位移了"。**

遮挡用 z 序：`armFar → legFar → torso → head → legNear → armNear`。
侧身时按 `rotY` 的符号翻转近/远侧顺序。

### 4.6 布景锚点（Set Piece）

道具从"角落图标"升级为"带锚点的布景"，2D 与 3D 各自实现同一份锚点坐标：

```ts
// video/setpiece-registry.ts
slide:  { deck: [x,y], ramp: {from,to,width}, rungs: [[x,y]...], bottom: [x,y] }
ladder: { rungs: [...], top: [x,y] }
table:  { top: [x,y], w, h }
```

动作通过锚点声明附着：`climb{ surface: 'ladder', steps: 4 }`、`slide{ surface: 'slide.ramp' }`。
**"爬上去"于是有了落点**，而不是把梯子图标摆在左边、角色摆在中间。

## 5. 分镜契约变更（R3 的修法）

### 5.1 语义扩张

`interaction` 当前被定义为"角色之间"。改为 `performance`，覆盖**单人动作**：

```jsonc
"performance": {
  "actor": { "id": "bear", "label": "小熊" },
  "motions": [
    { "op": "enter", "from": "left" },
    { "op": "climb", "surface": "ladder", "steps": 4 }
  ],
  "speech": "今天我要玩滑梯啦",     // 可选
  "caption": "一步一步往上爬"       // 可选
}
```

### 5.2 三层降级（不静默）

```
LLM 给出 performance  → 校验原语与参数 → 通过则用
                     → 不通过则用正则兜底（deriveInteractionFromText）
                     → 再不成则 warn + 该幕走 Puppet2D idle 入场（至少是全身角色）
```

当前的问题是第二层直接退到"白卡片 + emoji"且不报警。**至少要 warn，让"没有动作"成为可观测事件。**

### 5.3 可演性校验

`op` 与 `surface` 必须同时存在且匹配：
`slide` 无 `ramp` / `climb` 无 `ladder` → 丢弃该 motion 并 warn，不让渲染器猜。

## 6. 迁移路径

按"先立中枢、再补表达、最后换契约"的顺序，每步都能独立验收、独立回滚。

### 实施状态（2026-11-22）

| 阶段 | 状态 | 落地内容 |
|---|---|---|
| P0 姿态中枢 | ✅ 完成 | `src/video-remotion/src/character/pose.ts`（运动学唯一真源，483 行）；`ThreeActionStage.tsx` 从 700+ 行降到约 500 行、删除全部本地姿态函数；3D 抽帧 md5 与重构前一致 |
| P1 全身角色 | ✅ 完成 | `character/Puppet2D.tsx`（574 行）：头/耳/躯干/尾/双臂/双腿程序化分片 + 两段肢体求解 + z 序遮挡；已支持 `idle/speak/point/walk/climb/dribble/slide` 七个原语；**单人陈述/指认幕**（verb=point/speak）也按"能力匹配"下沉到全身角色，不再走徽章 |
| P2 布景锚点 | ✅ 完成 | `character/setpiece.ts`：梯子（立杆间距/横档起点/顶端余量/侧视参数）与滑梯（滑面/护边/平台/支柱/爬梯）几何唯一真源，2D `Ladder` 与 3D `SlideRig` 都从这里取数；新增"内容世界高度"函数（`ladderTopY` / `slideWorldHeight` / `actorHeadTop`）供取景使用。道具槽位由 `propSlot()` 给出坐标与尺寸，模板不再手写 `1430/690/280` |
| P3 契约切换 | ✅ 完成 | `performance`（`{ actors, actions[] }`）成为线上演出契约：模型直接给**有序动作表**，`interaction` 只作兼容读、文案正则降为最后兜底。一幕最多 3 个动作，`Puppet2D` 按"锚点接力"串演（每段起点安放到上一段终点），接缝做 8 帧姿态混合；`resolvePuppetSequence` 按动作自然时长分帧；台词气泡按 `speechAt` 延后到说话那一段。实测模型 5 幕全部按新契约输出（`walk→point→speak` / `walk→climb` / `slide` / `handover` / `cheer→speak`） |
| P4 景别层 | ✅ 完成 | `character/stage-layout.ts`：取景定律 `ppu = min(带高×景别占比÷主体高度, 带高÷内容高度)`；`shot: wide/medium/close` 按动作判定；2D/3D 共用同一地面线与同一相机反推公式；头像分支只在 `close` 档、贴地摆放。标题压顶按算术消除（实测梯子顶端 114px → 143px，标题底边 121px） |

**P4 落地后的三条补充**（都是这次真正踩到的）：

1. **"装下"和"画多大"是两个数，混成一个就出错**。第一次实现只传"这一幕最高的东西"（爬梯时是梯子顶端 2.75），拿去当主体尺寸算，缩放被压到 176，梯子缩到画面 365px、空了半个屏。正确做法是 `contentHeight`（不许裁）与 `subjectHeight`（站立身高 1.67）分开，取 `min` 的正是这两条约束。
2. **描边会吃掉留白**。2D 立杆是 `stroke-linecap: round`，视觉顶边比几何顶端高半个线宽（实测约 7px）。`titleGap` 从 20 提到 30，肉眼才真的看得出间隙。
3. **徽章的 `transform-origin` 必须是底边中点**。只把 `top` 改成计算值、缩放仍在中心，盒子会往上长出标题带——"改了一半"比不改更危险，因为它看起来已经用了新常量。

**景别判定的取舍**：`wide` 不是"无条件缩小"，而是"中景大小 + 必须装下布景"。所以 `wide` 与 `medium` 在单角色幕完全等价，只有布景比 `主体×0.62` 更高时才会自动后退（`ppu = min(...)` 的第二项）。这样既有成片的主体大小不变，新增高布景也不会顶穿标题。


**落地后回灌的三条经验**（都来自真实分镜，不是推演）：

1. **"单人幕没有身体"的根因不是缺原语，是缺路由**。`pose.ts` 早就能演 speak/point，但 `SceneLayer` 只把带 `puppet` 字段的幕送进 2D 分支。LLM 写 `verb: point` 时不带 `puppet`，于是整幕掉回徽章。修法是在装配层做能力匹配：单人 + 手势类 verb → 全身角色。**新增动作时先检查路由，再检查渲染器**。
2. **指认幕必须把被指的实物画出来**。只换身体不换道具，"小熊指着空气"比原来的小图标更差。`Puppet2D` 因此增加了 `props` 槽位（坐标 + 预先渲染好的 SVG 片段），业务道具仍由 `SceneLayer` 用 `PropArt` 渲染，组件本身不认识道具——新增道具零改动。
3. **回顾幕会被单个动作抢走**。真实第 5 幕"先爬楼梯，再滑滑梯，然后拍皮球"，`deriveInteractionFromText` 抓了"拍皮球"推出 dribble，回顾画面演成单拍球。补了两条判据：显式复述语（说清楚/复述/按顺序/总结一下）直接判空；一幕里出现**三种及以上**不同动作视为列举，同样判空。两个动作仍放行（"爬到顶上再滑下来"是真实的一幕流程）。这条只有跑真实分镜才会暴露——单元测试里我最初只断言"没有 puppet"，漏掉了它其实是 3D 拍球。

**回归防线**：`test/fixtures/slide-storyboard.json` 是从真实任务日志原样抠出的分镜，`scene-interaction.spec.ts` 用它锁路由决策（第 1 幕 point、第 2 幕推导 climb、第 3/4 幕保持 3D、第 5 幕判空）。`scripts/derive-storyboard-plan.ts` 让这条推导可以被渲染脚本复用，渲染脚本不再自己写正则猜动作——猜能出画面，但内容会错。

**与本文原始设想的两处偏差**（实施中发现更优，记录下来避免后人再走一遍）：

1. **P1 的资产前置被取消了**。原计划要拆 `assets/vector/animals/*.svg`，实际改为**纯程序化分片**：不读任何 SVG，直接用 `ActorRig`（耳型 / 尾型 / 配色 / 体型参数）画身体。好处是新增动物零资产成本、任意配色与体型都能演，坏处是"可爱度"上限受绘制代码限制。若后续要提升质感，再把这个组件换成拆片版即可，接口（`Pose` 进、画面出）不变。
2. **P2 的一部分被提前到了 P1**。因为 `climb` 如果没有梯子就是"对着空气攀爬"，视觉上无法验收，所以把 `Ladder` 作为 `Puppet2D` 的布景子组件一起做了，并让梯子横档间距直接读 `climbPose` 的 `stepH`——这样"手抓横档"在数学上必然对齐，而不是靠调参数碰运气。

### P3 契约切换

- `generate-video-content.ts` 改用 `performance`，`interaction` 保留兼容读
- 正则降为兜底；补 `warn` 日志（可观测）
- 补单测：单人动作（爬/走）必须产出 performance；无 motion 的幕必须 warn

**落地形态**：`performance = { actors, actions[] }`，`actions` 是**有序动作表**。

```
performance: {
  actors: [{ id: 'bear', label: '小熊', role: 'helper' }],   // 写一次，后续 action 继承
  actions: [
    { verb: 'walk' },
    { verb: 'point', propId: 'slide' },
    { verb: 'speak', speech: '看，这就是滑梯' },
  ],
}
```

读取顺序是三级，缺一级就退一级（退到静态构图才是彻底失败）：

```
performance（多动作） → interaction（单动作，兼容） → 文案正则（旧分镜兜底）
```

**三条关键取舍**：

1. **"能串演"要按能力判定，不是按字段有没有**。攀爬/滑降是**终态动作**（结束时角色已在梯顶或滑行终点），后面再接动作就是瞬移；`handover`/`lift-together` 需要两个身体，单骨架演不了。所以 `composePerformance` 先把"需要别的舞台"的动作提为主动作、其余丢弃，再对剩下的一串地面动作排序，丢掉的动作一律进 `warn`——**宁可少演一个，也不要演错顺序**。
2. **串演不能按每段自己的绝对坐标播**。`walk` 的默认轨迹是"画面左侧 → 正中"（-1.6 → 0），第二段若仍从自己的原点开始，角色会瞬移回左侧。规则改成"每段起点安放到上一段终点"（`carry = 上一段终点 − 本段局部起点`），位移量仍由注册表决定。
3. **接缝要混合，不能硬切**。走路末帧手臂在体侧、`point` 首帧手臂已平举，一帧跳过去像掉帧。`blendPose` 做 8 帧线性混合（混关节目标点，不混渲染结果，2D/3D 自动一致）。

**两个"看起来能用其实错了"的坑**：

- **气泡剧透顺序**。多动作幕里 `speech` 从第一帧就挂在画面上，"走过去→指一下→说话"的顺序第一秒就被说完。新增 `speechAt`（说话那一段的起点比例），`Puppet2D` 按它延迟显示——动作顺序才读得出来。
- **场景长度不是分镜时长**。最终场景长度由旁白音频决定（实测 8s 的幕被拉到 8.8s），而动作串是按 8s 分的帧，结果动作演完人还僵着 0.8s。`Puppet2D` 按 `场景真实帧数 ÷ 动作串总帧数` 拉伸（只拉不压：场景变短时宁截尾，不挤压动作）。

### P4 景别层

- `shot: wide | medium | close`；`Badge` 只在 `close` 使用
- 特写用于情绪/说话，全景用于动作——这也顺带解决"标题压角色头顶"

**落地形态**：`character/stage-layout.ts` 一条取景定律 + 三个景别占比。

```
ppu = min( 可用带高 × 景别占比 ÷ 主体高度,
           可用带高 ÷ 内容世界高度 )
```

| 概念 | 来源 | 含义 |
|---|---|---|
| 可用带高 | `STAGE.groundY − SUBJECT_TOP` = 856 − 151 = 705 | 标题下沿到地面的距离 |
| 内容世界高度 | `setpiece.ts` | 不许被裁的东西（梯子顶端、平台上坐姿头顶） |
| 主体高度 | `actorHeadTop(standHipY, scale)` | 角色"该画多大"，只看站立身高 |
| 3D 相机 | `z`、`lookY` 由 `ppu` 反推 | 地面永远落在 `STAGE.groundY`，与 2D 同一条线 |

实测：梯子顶端从 114px（压进标题 121px 内）变为 143px；2D 与 3D 地面从 856/827
统一到 856。取景的算术边界由 `test/unit/stage-layout.spec.ts` 守住（15 项）。
