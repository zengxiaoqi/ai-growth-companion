# 画面节点 ↔ 旁白对齐

> 解决的问题：图上挂着一张「白云」卡，旁白从头到尾没说过"云"。
> 孩子看见一个没被讲过的概念，比动画不同步严重一个量级。

## 1. 现象（真实数据，不是构造）

`scripts/probe-cue-anchors.ts --audit` 对 8 个内容场景 27 个节点跑严格审计：

| 场景 | 命中 | 没被念到的节点 |
|---|---|---|
| 水转了一圈 | 2/4 | 白云、雨滴 |
| 谁吃掉谁 | 3/3 | — |
| 种子长大了 | 1/3 | 幼苗、小花 |
| 沉还是浮 | 2/2 | — |
| 都是水果 | 4/4 | — |
| 大树的样子 | 3/4 | 树根 |
| 看不见的东西 | 2/4 | 个数、热量（只有单字「数」「热」） |
| 彩虹是怎么来的 | 2/3 | 彩虹 |

**6/27 = 22% 的节点从未被旁白念到**，而且集中在抽象/派生概念：云、雨、幼苗、花、根、彩虹——这些恰恰是 3-6 岁必须靠画面才懂的词。语音能锚定的都是「苹果」「香蕉」「石头」这类已经能听懂的实体。

s1 的旁白原文：「太阳把水晒热，水变成看不见的水汽飞到天上，遇冷又变回小水珠落下来，就这样转了一圈又一圈。」——**整句没有"云"字**，也没有"雨滴"（说的是"小水珠"）。

## 2. 根因

旁白和 `sceneGraph` 由**同一次 LLM 调用**产出（`generate-video-content.ts`），但两边从不互相校验：

- `describeGraphGrammar()` 只写「一句讲解 = 若干概念 + 一种关系」，从没要求 label 出现在旁白里；
- `video-generator.agent.ts` 的「旁白必须出现具体名词」只针对**主体**（供素材库检索图标），不覆盖 graph 节点；
- `visual-qa.service.ts` / `review-video-content.ts` 里没有任何节点↔旁白一致性校验（grep `节点` / `nodes` 无命中）；
- `subject` 别名和旁白说法不同步：`雨滴` 的 subject 是「雨」，旁白说「小水珠」——两边都对不上。

## 3. 修复

四处，都在生成端，渲染端一行没动：

1. **语法说明加硬约束**（`scene-graph.ts` `describeGraphGrammar()`）：label 必须逐字出现在本场景 narration 里；旁白没提到的概念不要放节点；subject 取旁白的说法。
2. **审计函数**（`scene-graph.ts` `auditGraphNarration()` / `formatCoverageFeedback()`）：判定口径**刻意从严**——label 或 subject 必须逐字出现。不做同义/单字兜底，因为「树根」靠单字「树」命中「大树」、「小花」靠「小」命中「小种子」都是静默错配：校验器说通过，画面却在讲一个没被讲过的概念。
3. **生成后审计 + 带话术重试**（`generate-video-content.ts`）：首轮不达标就把「哪个场景、哪些节点、旁白原文、怎么改」写进 `failures`，下一轮 prompt 带上。
4. **重试留优**：重试是整份重掷而不是定点修补，实测有样本被掷得更差（缺 2 个 → 缺 6 个），所以每轮只保留缺口最少的那份，不让更差的覆盖更好的。

## 4. 效果（真实 LLM 调用，生产提示词）

`scripts/probe-graph-narration-rule.ts --samples 3 --retry`，2 个主题 × 2 组 × 3 次采样，唯一变量是第 1 条规则在不在（对照组把规则那几行和 schema 描述还原成旧文案，实测少 336 字符）：

| | 节点总数 | 未被念到的节点 | 覆盖率 |
|---|---|---|---|
| 规则关 | 103 | 31 | 70% |
| 规则开 | 72 | **7** | **90%** |

缺失节点绝对数 31 → 7（**-77%**）。注意节点总数也从 103 降到 72：模型倾向"少放节点"而不是"把词补进旁白"，这是规则允许的取舍（宁可少讲一个概念，也不要放一张没讲过的卡），但意味着画面信息量会变薄，需要单独观察。

重试补齐（9 个首轮有缺失的样本）：

- 规则关组 6 个样本：缺 31 → 20，补回 11（35%），其中 1 例被掷得更差（2 → 6）
- 规则开组 3 个样本：缺 4 → **0**，全部补到 100%

## 5. 已知局限

- **figure 场景没覆盖**。`figure.labels` 同样有"画上有字、话里没说"的风险，本次只审 `sceneGraph`。彩虹主题两个臂都退成 figure，因此 0 节点。
- **重试不是定点修补**，是带话术重掷，可能引入新的缺失；已用"留优"兜住，但最坏情况仍是 3 次都用不上。
- **校验只报不阻断**：用尽重试仍不达标会放行并 `warn`，因为退回 `buildFallbackStoryboard`（通用卡片）比"多一张没讲过的卡"更糟。
- 重试最多回喂 2 个场景的错误，避免 prompt 预算被吃光。

## 6. 复验

```bash
cd src/backend

# 不跑 TTS，纯审计现有场景（快）
npx ts-node --transpile-only scripts/probe-cue-anchors.ts --audit

npx ts-node --transpile-only scripts/probe-cue-anchors.ts --json ../video-remotion/out/cue-anchors.json

# 提示词规则的受控 A/B（会真实调用 LLM）
npx ts-node --transpile-only scripts/probe-graph-narration-rule.ts --samples 3 --retry

npx jest --testPathPattern="(scene-graph|generate-video-content)"
```

## 7. 与"动作挂词"的关系

原计划是「让图形语义动作跟着念到的词走」。探针数据判它暂时不成立：锚点覆盖率只有 78%，缺口正好落在需要画面解释的抽象概念上，且 s1 里带语义动作的「白云」完全没有锚点——做出来会是一屏两套时间轴，比现在更乱。

顺序应当是：**先把节点和旁白对齐（本文），覆盖率上来之后再做动作挂词**。那时验收口径用锚点偏差，不用活跃块占比。
