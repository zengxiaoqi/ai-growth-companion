# 混合式智能素材系统方案

## Summary
- 现状问题是“关键词/role 直查”，不理解场景意图，也不评价候选图是否真适合。
- 推荐升级为：视觉意图解析 -> 本地/开放库多路检索 -> 候选评分 -> 低置信度 AI 生成 -> 写回 manifest 复用。
- 当前仓库没有现成图片生成入口，所以图片生成做成可配置 provider；未配置时只跑智能检索，不阻塞视频生成。

## Key Changes
- 增加 `VisualIntent`：
  - 每个场景解析出 `subject`、`action`、`attributes`、`environment`、`composition`、`queryZh/queryEn`、`mustHaveTerms`。
  - 例如孔雀开屏生成查询：`male peacock displaying tail feathers CC0`、`Indian peafowl fan tail public domain`。
- 增加智能检索与评分：
  - 顺序仍是本地 `manifest.json` -> Openverse CC0 -> Wikimedia CC0 -> AI 生成 -> 内联 SVG -> 圆圈文字。
  - 对候选图按 license、尺寸、主体匹配、动作匹配、背景适配、横竖比例、透明/可抠图程度打分。
  - 低于阈值的外部图不使用，并打印拒绝原因。
- 增加 AI 素材生成 provider：
  - 新增 `IMAGE_PROVIDER_MODE=off|hybrid`、`IMAGE_PROVIDER_BASE_URL`、`IMAGE_PROVIDER_API_KEY`、`IMAGE_PROVIDER_TIMEOUT_MS`。
  - 只在开放素材无高置信候选时调用。
  - 生成结果保存到 `public/.generated/assets/...`，并写入 `asset-manifest.json`，下次优先复用。
- 增加可观测性：
  - 每场景打印 `visualIntent`、检索 query、候选数量、评分最高项、拒绝原因、最终策略。
  - 渲染日志明确输出 `visualStrategy=imageAsset|generatedImage|inlineSvg|circleText`，避免背景命中被误读成主角命中。

## Test Plan
- 单测覆盖：
  - `孔雀` 能解析为 `subject=peacock`，并生成英文扩展查询。
  - 本地无孔雀素材时，先查 Openverse/Wikimedia；低分候选被拒绝。
  - 外部检索无合格候选且开启 `IMAGE_PROVIDER_MODE=hybrid` 时调用图片生成 provider。
  - 生成素材写入 manifest 后，下一次走本地缓存。
- 运行：
  - `cd src/backend && npm run test -- --testPathPattern="visual-asset|video-generation-agent"`
  - 必要时再跑 `npm run lint`。

## Assumptions
- AI 生成默认关闭，只有配置 `IMAGE_PROVIDER_MODE=hybrid` 和 provider 环境变量后启用。
- 生成素材按内部教学素材缓存处理，必须记录 provider、prompt、license/usage 字段。
- 圆圈文字保留为最终兜底，但必须带完整未命中诊断日志。
