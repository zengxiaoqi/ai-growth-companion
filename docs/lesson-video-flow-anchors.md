# 光点挂词：谁亮着 = 谁正在被讲到

> 承接 `lesson-video-action-anchors.md`。节点自己的语义动作挂上词之后，剩下唯一还挂在
> 整屏时钟上的东西是**光点**——它决定哪个节点处于高亮，也就是孩子此刻在看哪个概念。

## 一、改之前是什么状态

光点沿箭头走，`t` 来自 `storyProgress`（入场结束 → 本屏收尾，线性）。

- **非循环关系**（chain / growth / split / group）：一条路径按整屏时长走完，
  到达某节点的帧与旁白念到该词无关。chain 实测（三节点、词在 24/96/168 帧）：
  光点在第 57 帧到「兔子」、第 134 帧到「狐狸」，比旁白早 39 / 34 帧（1.3s / 1.1s）。
- **循环关系**（cycle）：`t = (frame - warmup) / FLOW_PERIOD`，而 `FLOW_PERIOD = 84`。
  一圈 2.8 秒，四个节点每 21 帧换一次高亮——**一屏里四个概念各被点亮四次**。
  实测水循环场景 345 帧：四个节点分别在 29 / 50 / 71 帧亮起，而旁白分别在第
  121 / 235 / 275 帧才念到它们。

第二点比第一点严重：不是"略有偏差"，是高亮在打拍子。高亮是"现在讲这个"的唯一
视觉信号，打拍子等于这个信号不携带信息。

## 二、做法

一条边 = 从 A 说到 B 的那一段话。

```
stops[0]   = 旁白在 A 之前最后念到的帧     ← 动身
stops[i+1] = 念到 target[i] 的帧           ← 到达
```

模板侧按边分段做**分段线性**的 `t`：帧落在哪一段，就按该段时长在段内插值，
段的 `t` 区间边界按边长归一——所以光点仍然贴着箭头走，只是速度由旁白决定
（"这句话说多久，这段路就走多久"）。

三个配套决定：

1. **高亮交接从"走到半段"改成"到达才点亮"**。时钟驱动时半段交接是对的（否则光点
   刚离开 A，B 就抢先发光）；挂词驱动时到达那一刻 *就是* 这个词被念出来的那一刻，
   提前半段点亮等于把注意力提前搬到还没讲的概念上。两种口径用 `token.anchored`
   分开，时钟路径逐像素不变。
2. **循环关系走完第一圈就把高亮钉住**，光点继续一圈圈转（"一圈又一圈"的语义在
   旁白里确实存在），但不再改高亮。不这么做，讲完之后高亮还在按 21 帧换人。
3. **整条路径一起回退**。缺任一个词、某段短于 `FLOW_MIN_SEG = 12` 帧、图上节点顺序
   与旁白顺序不一致，任一条成立就整条路径退回时钟驱动——不做"半条挂词半条挂钟"，
   那会让同一屏出现两套节奏。回退是静默的，所以渲染日志里加了 `flowAnchors` 告警
   （`auditFlowOrder()` 比对"图上顺序"与"发音帧顺序"）。

数据来源没有新增字段：直接复用 `scene.actionAnchors`（上一轮的节点锚点表，
`start` 就是该词的发音帧）。新增的只有一个探针开关 `scene.flowAnchors = false`，
用来把"光点挂词"和"节点动作挂词"分开量化。

## 三、效果（同源受控，唯一变量是 `flowAnchors`）

读数方式：读画面像素，不看代码推理。节点被点亮时它下方的标签胶囊底色会变成强调色，
按强调色数像素得到逐帧的亮/不亮，onset = 第一次进入"连续 4 帧都亮"的帧
（卡片入场过渡帧会短暂露出强调色，单看第一次超阈值会差出 70 帧）。
"对拍命中率" = 每帧亮着的节点 == 旁白最近一次念到的节点的帧占比。

### cycle（真实 TTS，水循环，345 帧）

| 节点 | 旁白念到 | 挂词后亮起 | 时钟驱动亮起 | 时钟驱动亮起次数 |
|---|---|---|---|---|
| 小水滴 | 22 | 18（场景起始即亮） | 18 | 4 |
| 水蒸气 | 121 | **121（+0）** | 29（-92） | 4 |
| 小水珠 | 235 | **235（+0）** | 50（-185） | 4 |
| 云 | 275 | **275（+0）** | 71（-204） | 4 |

- 对拍命中率：**100.0%（313/313）** ← 时钟驱动 **24.9%（78/313）**
- 每个节点亮起次数：挂词 1 次；时钟 4 次

### chain（三节点、两段路径，合成时间轴 24/96/168）

| 节点 | 旁白念到 | 挂词后 | 时钟驱动 |
|---|---|---|---|
| 青草 | 24 | 18（场景起始即亮） | 18 |
| 兔子 | 96 | **96（+0）** | 57（-39） |
| 狐狸 | 168 | **168（+0）** | 134（-34） |

- 对拍命中率：**98.2%（163/166）** ← 时钟驱动 **54.2%（90/166）**
- 剩下的 3 帧错配是两张卡入场时短暂同时露强调色（测量口径的瞬态，非画面问题）

### 回归

无锚点的老 props 渲 30 帧与改动前基线对拍：最大均值差 **0.0005**、最大单点差
**4 灰阶**——与既有二次渲染抖动同量级，老任务重渲不变。

## 五、已知局限

1. **只验证了 cycle 与 chain 两种拓扑**。split / group 是多条独立路径（每条一段），
   分段逻辑与 chain 同构，但没有真实样本渲染验证。
2. **chain 用的是合成时间轴**（24/96/168），验证的是"帧 → 段 → 到达帧"的映射；
   真实旁白的语音分布不是等距的，但映射本身与分布无关。
3. **图上顺序与旁白顺序不一致的场景会静默回退**（现在会进 warn 日志）。这类场景
   需要先修生成端的节点顺序，不是渲染端能解决的。
4. **时间基逻辑写在模板字符串里**，无法单元测试——只能靠渲染对拍。
   `check-generated-lesson-tsx.js` 里加了 `flowStops` / `tAtStops` / `FLOW_MIN_SEG`
   三个必备 token，防止以后改模板时被静默删掉。
5. 光点仍按**边长归一**分配段内位置，所以两条边时长相同但长度差很多时，速度差异
   是可见的。这是有意为之（"路要走完"优先于"速度均匀"），但如果观感上像忽快忽慢，
   第一个该调的参数是 `FLOW_MIN_SEG` 与是否允许跨段匀速。
